## MD-Models

Отлично, именно так и работает MD-Models на практике. Вы правильно поняли логику: **1. Модель -> 2. Генерация -> 3. Использование**. Вот пошаговая инструкция для вашего кейса с заказами.

### 🚀 Практический план: от модели до скрипта обработки

#### Шаг 1: Создание Модели (Class)
Создайте файл `модель_заказа.md`. Это и есть ваш **Class** — формальное описание структуры данных.

```markdown
### Заказ
- **id**
    - Type: string
    - Description: Уникальный номер заказа (например, 2025-12-001)
- **клиент**
    - Type: Клиент
- **детали**
    - Type: ДеталиЗаказа
- **исполнители**
    - Type: Исполнитель[]
    - Description: Список исполнителей (опционально)

### Клиент
- **имя**
    - Type: string
- **телефон**
    - Type: string
- **email**
    - Type: string
    - Required: false

### ДеталиЗаказа
- **описание**
    - Type: string
- **создан**
    - Type: date
- **статус**
    - Type: string
- **цена**
    - Type: number
- **предоплата**
    - Type: number
    - Required: false

### Исполнитель
- **имя**
    - Type: string
- **задачи**
    - Type: string[]
- **оклад**
    - Type: number
```

#### Шаг 2: Генерация кода из модели
Это этап **«согласно классу данные через md-models конвертируется»**. Установите и используйте CLI для создания готового Python-класса.

1.  **Установка MD-Models CLI** (требуется Rust):
    ```bash
    cargo install md-models-cli
    ```
2.  **Генерация Pydantic-модели** (современный стандарт для данных в Python):
    ```bash
    md-models convert модель_заказа.md --format python-pydantic > models.py
    ```
    В файле `models.py` вы получите готовые, строго типизированные Python-классы `Заказ`, `Клиент` и т.д.

#### Шаг 3: Создание и парсинг данных
Теперь этап **«читается»**. Вы создаете файлы с данными в удобном Markdown-формате, а скрипт читает их.

1.  **Создайте файл с данными** `заказ_001.md`:
    ```markdown
    ### Заказ
    - **id**: 2025-12-001
    - **клиент** ### Клиент
        - **имя**: Ахметзянова Виктория
        - **телефон**: 89173474746
        - **email**: vikarb@yandex.ru
    - **детали** ### ДеталиЗаказа
        - **описание**: Изготовление 5 клише 50x10 мм
        - **создан**: 2025-12-26
        - **статус**: в процессе
        - **цена**: 2500
        - **предоплата**: 1500
    - **исполнители** ### Исполнитель
        - **имя**: Перепелкин Артемий
        - **задачи**: ["Подготовка макета", "Согласование"]
        - **оклад**: 1000
    ```
2.  **Напишите скрипт обработки** `обработчик.py`:
    ```python
    import json
    from mdmodels import Parser
    from models import Заказ  # Импортируем сгенерированный класс

    # 1. Инициализируем парсер MD-Models
    parser = Parser()

    # 2. Читаем Markdown-файл и парсим его в объект Python
    with open('заказ_001.md', 'r', encoding='utf-8') as f:
        markdown_text = f.read()

    # Парсим текст согласно модели "Заказ"
    данные_заказа = parser.parse(markdown_text, target_model=Заказ)

    # 3. Теперь 'данные_заказа' — это объект класса 'Заказ'
    # Мы можем обращаться к его атрибутам
    print(f"Номер заказа: {данные_заказа.id}")
    print(f"Клиент: {данные_заказа.клиент.имя}")
    print(f"Общая цена: {данные_заказа.детали.цена} руб.")

    # 4. Автоматический расчёт (главная цель скрипта)
    # Пример 1: Считаем остаток к оплате
    предоплата = данные_заказа.детали.предоплата or 0  # Если поля нет, будет 0
    остаток = данные_заказа.детали.цена - предоплата
    print(f"Остаток к оплате: {остаток} руб.")

    # Пример 2: Считаем прибыль с исполнителя (20% от оклада)
    if данные_заказа.исполнители:
        for исполнитель in данные_заказа.исполнители:
            прибыль = исполнитель.оклад * 0.2
            print(f"Прибыль с исполнителя '{исполнитель.имя}': {прибыль} руб.")

    # 5. Пример сохранения в JSON для обмена или базы данных
    with open('заказ_001.json', 'w', encoding='utf-8') as f:
        # Конвертируем объект Pydantic в dict, затем в JSON
        json.dump(данные_заказа.dict(), f, ensure_ascii=False, indent=2)
    print("\n✅ Данные сохранены в 'заказ_001.json'")
    ```

### 🧪 Как это работает в реальности

1.  Вы запускаете скрипт: `python обработчик.py`
2.  Парсер MD-Models читает `заказ_001.md`.
3.  Он **сопоставляет заголовки (`###`) и списки (`-`)** со структурой класса `Заказ`, который был сгенерирован из модели.
4.  Данные преобразуются в объект Python, и вы получаете доступ ко всем полям: `данные_заказа.детали.цена`.
5.  Скрипт выполняет бизнес-логику (расчёт остатка, прибыли) и экспортирует результат.

### 💡 Ключевые преимущества такого подхода

*   **Валидация на лету**: Если в `заказ_002.md` в поле `цена` будет текст, парсер выдаст понятную ошибку при запуске скрипта.
*   **Автодополнение в редакторе**: Импортировав `models.py`, ваша среда разработки (VS Code, PyCharm) будет подсказывать `данные_заказа.клиент.` и показывать доступные поля (`имя`, `телефон`).
*   **Масштабирование**: Чтобы обработать все заказы в папке, добавьте в скрипт цикл по файлам `.md`.
