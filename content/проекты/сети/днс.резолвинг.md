# DNS: резолвинг имён в сети А3

Заметка для переноса в проект **про.а3.сети**. Здесь — реализация схемы DNS, согласованной с СТАНДАРТОМ ВС 4 (п. 7.2): обращение к устройствам по доменному имени на двух уровнях — внутри салона (локальная сеть) и между салонами (объединённая VPN-сеть).

Стандарт ВС 4 описывает только *возможности* DNS и их согласование с wpid; конкретная реализация (серверы, зоны, форвардинг) — предмет этой заметки.

## Именование (что резолвим)

- Зона: **`.internal`** (зарезервирована IANA для внутренних сетей; в публичном DNS не существует).
- FQDN узла — разворот полной формы wpid с добавлением зоны: `loc-01.sws-01` → `sws-01.loc-01.internal`.
- Локально (в пределах салона) короткое имя `sws-01` дополняется search domain `loc-01.internal` → `sws-01.loc-01.internal`.
- Обратные (PTR) зоны — на `10.10X.0.0/16`.

Охват корпоративной зоны: **только рабочие места и серверы** (sws, gsw, pos, srv). Принтеры/МФУ/камеры и прочее — по желанию, отдельным решением.

## Архитектура

Два звена:

| Звено | Где живёт | Что делает |
|---|---|---|
| Корпоративная зона `.internal` | VPS (там, где headscale) | авторитативный DNS: записи всех салонов + PTR |
| Локальный резолвер салона | шлюз sing-box каждого салона | отвечает за свою зону `loc-XX.internal`, остальной `.internal` форвардит на VPS, интернет — вверх |

Роутеры (TP-Link/Keenetic) в резолвинге не участвуют — только раздают клиентам адрес DNS-шлюза и search domain по DHCP.

## Составные части

### 1. VPS: headscale + авторитативный DNS

- Рядом с headscale поднимается авторитативный DNS (NSD/Knot/PowerDNS — зона копеечная), авторитативен для `internal`.
- Содержит A-записи всех рабочих мест и серверов всех салонов + обратные зоны (PTR).
- Чтобы dnsmasq салонов ходил на него по tailnet, на VPS поднимается узел Tailscale (сам headscale — только координатор, узлом не является). Адрес DNS — tailnet-IP `100.x.y.z`.

### 2. Шлюз салона: sing-box + dnsmasq

Шлюз — Linux-хост, последняя сборка sing-box со встроенным Tailscale. Роль в tailnet:

```
inbound.tailscale:
  route_address: ["10.10X.0.0/16"]   # анонс подсети салона
```

Рядом с sing-box на том же хосте — **dnsmasq** (резолвер салона), слушает LAN-адрес шлюза, порт 53. Правила (эскиз, Салон 14):

```
listen-address=10.101.0.2
bind-interfaces
no-resolv

# своя зона — отвечаем сами из локального списка (работает без VPN)
local=/loc-01.internal/
addn-hosts=/etc/a3-hosts          # 10.101.2.1 sws-01.loc-01.internal и т.д.

# остальной .internal (другие салоны) — на корпоративный DNS (VPS)
server=/internal/100.x.y.z

# интернет
server=8.8.8.8
server=1.1.1.1
```

Ключевая механика: `local=/loc-01.internal/` делает dnsmasq авторитативным для своей зоны — запросы в неё не форвардятся, отвечает из `a3-hosts` (работает даже когда VPN лежит). `server=/internal/<VPS>` ловит остальные поддомены `internal` (loc-02, loc-03…). Более специфичное правило (своя зона) выигрывает.

### 3. Клиенты

- DHCP на роутере раздаёт: DNS = LAN-адрес шлюза sing-box + search domain `loc-01.internal` (DHCP option 15/119; поддержка у Keenetic и TP-Link разная — проверить).
- Статические машины: DNS прописывается вручную или в базовом образе ОС.

## Потоки запросов

1. **Локально, без VPN:** `sws-01` → клиент дописывает search domain → `sws-01.loc-01.internal` → dnsmasq из `a3-hosts` → `10.101.2.1`.
2. **Между филиалами:** `sws-01.loc-01.internal` из салона 10 → dnsmasq салона 10 (зона не его) → по tailnet на VPS → `10.101.2.1`. Обратный пакет: шлюз салона 10 (subnet-route) → туннель → шлюз салона 14 → машина.

## Отказоустойчивость

- VPN/VPS лёг → локальные имена живут (dnsmasq отвечает из `a3-hosts`), межфилиальные нет (они и не нужны без связи).
- dnsmasq лёг → на Windows частично спасает NetBIOS/LLMNR.
- VPS лёг → страдают только межфилиальные имена.

## Нюансы

- **`.local` не использовать** (mDNS/Bonjour, unicast-DNS конфликтует). Поэтому `.internal`.
- sing-box DNS-модуль с dnsmasq не конфликтует: порт 53 за dnsmasq; sing-box DNS решает только собственную маршрутизацию шлюза.
- `a3-hosts` каждого салона генерируется из мастер-таблицы (как `hwid_fleet.py`) — единый источник правды, ручное ведение исключено.
- Поддержка `inbound.tailscale` с `route_address` в sing-box — экспериментальная; сверить с используемой сборкой (последняя — ок).
