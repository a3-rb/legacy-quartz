# Шпаргалка: Обработка оцифрованного видео в ffmpeg

---

> [!info]
> Эта заметка содержит общие команды ffmpeg, которые можно исопльзовать для обработки оцифровок видео и других медиафайлов

---

## Общий порядок действий

```
1. АНАЛИЗ ИСХОДНИКА    →   ffprobe, проверка FPS, ключевых кадров, геометрии
2. ОПРЕДЕЛЕНИЕ ТРИММИНГА →   внешние инструменты / визуально найти синие экраны
3. ПРОВЕРКА КАДРИРОВАНИЯ →   сгенерировать превью с сеткой, убедиться что не нужно
4. ВЫБОР СТРАТЕГИИ КОДИРОВАНИЯ →   H.264/H.265 + программное/аппаратное
5. ОБРАБОТКА            →   запуск финальной команды
6. ПРОВЕРКА РЕЗУЛЬТАТА  →   выборочный просмотр, сверка длительности
```

---

## Этап 1: Анализ исходного файла

> [!tip]
> Этот этап можно пропускать.
### 1.1 Базовая информация о файле

```bash
ffprobe "имя_файла.mp4"
```

**Что даёт:** контейнер, кодек, разрешение, FPS, битрейт, длительность, количество дорожек.

### 1.2 Проверка стабильности частоты кадров (VFR/CFR)

```bash
ffprobe -v quiet -select_streams v:0 -show_entries frame=pts_time,pict_type -of csv=p=0 "имя_файла.mp4" | head -n 30
```

**Что даёт:** метки времени и типы первых 30 кадров. Если интервалы между кадрами «плавают» — видео с переменной частотой кадров (VFR). Для точной обрезки потребуется перекодирование.

### 1.3 Поиск ключевых кадров (I-кадров) — ВСЕ

```bash
ffprobe -v quiet -skip_frame nokey -select_streams v:0 -show_entries frame=pts_time -of csv=p=0 "имя_файла.mp4"
```

**Что даёт:** полный список времён всех I-кадров. Нужен для определения возможности обрезки без перекодирования (`-c copy`).

**Как читать вывод:**
- Если нужная точка обрезки точно совпадает с I-кадром → можно резать без перекодирования
- Если между I-кадрами большой промежуток (как в нашем случае 7–15 секунд) → перекодирование обязательно

### 1.4 Поиск I-кадров в начале файла (первые 30 секунд)

```bash
ffprobe -v quiet -skip_frame nokey -select_streams v:0 -show_entries frame=pts_time -of csv=p=0 "имя_файла.mp4" | grep -E "^0:00:[0-2][0-9]"
```

**Что даёт:** I-кадры в диапазоне 00:00 – 00:29 для точного определения точки начала обрезки.

### 1.5 Поиск последних I-кадров в файле

```bash
ffprobe -v quiet -skip_frame nokey -select_streams v:0 -show_entries frame=pts_time -of csv=p=0 "имя_файла.mp4" | tail -n 10
```

**Что даёт:** последние 10 I-кадров для определения точки конца обрезки.

### 1.6 Предпросмотр кадрирования (сетка + рамка)

```bash
ffmpeg -ss 00:05:00 -i "имя_файла.mp4" -t 10 -vf "drawgrid=w=40:h=40:t=2:c=red,drawbox=x=0:y=0:w=640:h=480:color=green:t=2" -c:v libx264 -crf 18 -an "preview_crop_grid.mp4"
```

**Что даёт:** 10-секундный ролик с красной сеткой (шаг 40px) и зелёной рамкой по периметру. Открыть в плеере и посчитать пиксели чёрных полос со всех сторон.

**Параметры фильтра кадрирования:**

```
crop=ширина:высота:x:y
```

- x — отступ слева
- y — отступ сверху
- ширина = 640 - (слева + справа)
- высота = 480 - (сверху + снизу)

## Этап 2: Обрезка (тримминг)

### 2.1 Когда можно резать без перекодирования (I-кадры совпадают)

```bash
ffmpeg -i "исходник.mp4" -ss 00:00:12 -to 03:04:45 -c copy "результат.mp4"
```

**Условие:** обе временны́е метки должны приходиться точно на I-кадры.

### 2.2 Когда нужно перекодирование (наша ситуация)

Обязательно при:
- переменной частоте кадров (VFR)
- больших промежутках между I-кадрами
- необходимости кадрирования
- необходимости сжатия

## Этап 3: Стратегии кодирования

### Сравнительная таблица

| Кодер | Тип | Совместимость | Размер файла (3ч 640×480) | Скорость | Качество |
|-------|-----|:---:|:---:|:---:|:---:|
| `libx264` + CRF 20 | Программный | ★★★★★ | ~4–5 ГБ | ★★ | ★★★★★ |
| `libx265` + CRF 23 | Программный | ★★★ | ~1.5–2.5 ГБ | ★ | ★★★★★ |
| `h264_qsv` | Аппаратный (Intel) | ★★★★★ | ~3.5 ГБ | ★★★★★ | ★★★★ |
| `hevc_qsv` | Аппаратный (Intel) | ★★★ | ~2 ГБ | ★★★★★ | ★★★★ |
| `h264_nvenc` | Аппаратный (NVIDIA) | ★★★★★ | ~3.5 ГБ | ★★★★★ | ★★★★ |

### Выбор кодека:

- **H.264** — максимальная совместимость, играет везде
- **H.265/HEVC** — в 2 раза компактнее, но старые устройства могут не поддерживать

### Выбор способа кодирования:

- **Программный (libx*) —** качество выше, скорость ниже
- **Аппаратный (qsv/nvenc/amf) —** скорость выше, качество чуть ниже

## Этап 4: Финальные команды

### 4.1 Программный H.264 (баланс качество/скорость)

```bash
ffmpeg -i "исходник.mp4" -ss 00:00:12 -to 03:04:45 -c:v libx264 -crf 20 -preset fast -c:a aac -b:a 128k "результат.mp4"
```

| Параметр             | Значение                                            |
| -------------------- | --------------------------------------------------- |
| `-c:v libx264`       | программный кодер H.264                             |
| `-crf 20`            | качество (0–51, меньше = лучше, 18–23 — оптимально) |
| `-preset fast`       | скорость кодирования (medium/fast/faster/veryfast)  |
| `-c:a aac -b:a 128k` | аудио AAC 128 кбит/с                                |

> [!tip]
> Для лучшего сжатия и качества лучше использовать `--crf 23 --preset medium`


### 4.2 Аппаратный Intel Quick Sync H.264 (максимальная скорость)

```bash
ffmpeg -qsv_device 0 -i "исходник.mp4" -ss 00:00:12 -to 03:04:45 -c:v h264_qsv -b:v 2500k -c:a aac -b:a 128k "результат.mp4"
```

| Параметр        | Значение                                            |
| --------------- | --------------------------------------------------- |
| `-qsv_device 0` | устройство Intel GPU (нужно при ошибке MFX session) |
| `-c:v h264_qsv` | аппаратный кодер Intel                              |
| `-b:v 2500k`    | битрейт видео (для 640×480 хватает 2000–3000k)      |

> [!warning]
> В новых версиях ffmpeg Intel Quick Sync удалён, команда не работает.

### 4.3 Программный H.265 (максимальное сжатие)

```bash
ffmpeg -i "исходник.mp4" -ss 00:00:12 -to 03:04:45 -c:v libx265 -crf 23 -preset medium -c:a aac -b:a 128k "результат.mp4"
```

> [!Warning]
>  Клиенты могут столкнуться с проблемами при воспроизведении этого кодека. Лучше H.254


### 4.4 С кадрированием (добавляется фильтр `-vf crop`)

```bash
ffmpeg -i "исходник.mp4" -ss 00:00:12 -to 03:04:45 -vf "crop=600:440:20:20" -c:v libx264 -crf 20 -preset fast -c:a aac -b:a 128k "результат.mp4"
```

где `crop=600:440:20:20` означает:
- итоговая ширина 600px, высота 440px
- отступ слева 20px, сверху 20px

## Проверка результата

```bash
ffprobe "результат.mp4"
```

**Проверить:**
- Длительность: должна быть ~03:04:33 (03:04:45 минус 12 секунд)
- Кодек: h264
- Разрешение: 640×480
- Битрейт видео и аудио

**Визуальная проверка:**
- Открыть начало → нет синего экрана
- Открыть конец → нет синего экрана
- Промотать середину → качество устраивает

## Шпаргалка по параметрам ffmpeg

| Параметр | Описание |
|----------|----------|
| `-i файл` | Входной файл |
| `-ss ЧЧ:ММ:СС` | Начало отрезка |
| `-to ЧЧ:ММ:СС` | Конец отрезка |
| `-t ЧЧ:ММ:СС` | Длительность (альтернатива `-to`) |
| `-c copy` | Копировать без перекодирования |
| `-c:v кодек` | Видеокодек |
| `-c:a кодек` | Аудиокодек |
| `-crf N` | Качество (0–51, для x264 по умолчанию 23) |
| `-b:v Nk` | Битрейт видео в кбит/с |
| `-b:a Nk` | Битрейт аудио в кбит/с |
| `-preset имя` | Скорость кодирования x264/x265 |
| `-vf "фильтр"` | Видеофильтр |
| `-an` | Без аудио |
| `-vn` | Без видео |
| `-qsv_device N` | Выбор устройства Intel QSV |
