# СТАНДАРТ ВС 1

Стандарт: Наименование рабочих файлов в компании «А3»
Дата введения: 2025-12-22
Дата ревизии: 2025-12-22

---

## 1 Назначение

Данный стандарт устанавливает единые правила именования рабочих файлов в компании «А3». Цель стандарта — обеспечить однозначную идентификацию файлов, упростить их поиск и сортировку, а также заложить основу для возможной автоматизации процессов. Стандарт предлагает два взаимозаменяемых формата записи: **Упрощённый** (для повседневного использования) и **УДИ-совместимый** (для технической интеграции и системного учёта).

---

## 2 Общие положения и термины

**2.1 Упрощённый формат:** Основной формат записи имени файла на кириллице. Использует нотацию, где каждый сегмент начинается с заглавной буквы, а для разделения слов внутри сегмента рекомендуется нижнее подчёркивание. Не включает технический класс УДИ. Предназначен для максимальной понятности.

**2.2 УДИ-совместимый формат:** Формат записи на латинице, соответствующий принципам стандарта **R 5 (Универсальное доменное имя)**. Использует нотацию `snake_case` (слова разделяются нижним подчёркиванием) и всегда начинается с класса УДИ `a3`. Обеспечивает машинную обработку и интеграцию в общую систему индексации.

**2.3 Взаимозаменяемость:** Любое имя в Упрощённом формате может быть однозначно преобразовано в УДИ-совместимый формат и наоборот с помощью формальных правил транслитерации и преобразования нотаций. Основным для повседневного применения является Упрощённый формат.

**2.4 Структурные элементы имени:**

- **Префикс:** Начальная часть имени, определяющая общую принадлежность файла. В Упрощённом формате может начинаться с подкласса или типа работы. В УДИ-формате всегда начинается с `a3.{подкласс}`.
- **Домен/Сегмент:** Часть имени между точками, несущая определённую смысловую нагрузку (например, имя клиента, идентификатор).
- **Обязательные элементы:** Элементы, которые должны присутствовать всегда. Их пропуск без указания пустого поля не допускается.
- **Необязательные элементы:** Элементы, которые могут отсутствовать. Если они пропущены, их поле может оставаться пустым.
- **Пустое поле:** Показатель пропущенного элемента, обозначаемый двумя точками подряд (`..`).

**2.5 Основные подклассы:**

- **`ord` / `Заказ`:** Файлы, связанные с заказами клиентов. Имеет сложную структуру. *Наиболее важный подкласс.*
- **`tml` / `Шаблон`:** Файлы-шаблоны для различных работ.
- **`doc` / `Документ`:** Внутренние документы компании (инструкции, регламенты, логотипы).
- **`adm` / `Администрирование`:** Файлы, связанные с управлением и планированием (графики, отчёты).
- **`inf` / `Справка`:** Справочные материалы.

## 3 Общие правила составления имён

1. **Разделитель:** В качестве разделителя доменов (сегментов) используется точка (`.`).
2. **Запрещённые символы:** В именах файлов не допускается использование символов, запрещённых файловой системой (`/ \ : * ? " < > |`).
3. **Регистр и разделение слов:**
    - *Упрощённый формат:* Каждый сегмент начинается с заглавной буквы. Для разделения слов внутри одного сегмента **рекомендуется** использовать нижнее подчёркивание (`_`). Использование пробела **допускается, но не рекомендуется**. Примеры: `Лазерная_Резка`, `Мария_Иванова` (рекомендуется) или `Лазерная Резка`, `Мария Иванова` (допустимо).
    - *УДИ-формат:* Все буквы строчные. Для разделения слов используется только нижнее подчёркивание (`_`). Пример: `laser_cut`, `maria_ivanova`.
4. **Расширение файла:** Стандартное расширение файла, указываемое в конце имени после последней точки. Не является частью логического имени по стандарту, но обязательно для файлов.

## 4 Структура подклассов

### 4.1 Подкласс `Заказ` (`ord`)

Служит для именования файлов, создаваемых в процессе выполнения заказа клиента.

**4.1.1 Полная структура (УДИ-совместимый формат):**

```
a3.ord.<тип_работы>.<имя_клиента>.<ид_клиента>.<дата_заказа>.<номер_файла>.<версия>.<описание>.<расширение>
```

**Где:**
- `a3.ord` — обязательный префикс (класс и подкласс).
- `<тип_работы>` — обязательный. Код типа работы в формате `snake_case` (см. таблицу 1).
- `<имя_клиента>` — обязательный, но может быть пустым полем. Имя клиента в транслитерации, `snake_case`.
- `<ид_клиента>` — обязательный, но может быть пустым полем. Уникальный идентификатор клиента: номер телефона (только цифры), ID из CRM-системы или другой идентификатор, не содержащий запрещённых символов (особенно точки).
- `<дата_заказа>` — **необязательный**. Дата в формате `ГГГГММДД`. Если не указана, элемент пропускается полностью (без пустого поля). Для указания периода дат используется двойной дефис `--` (например, `20250312--20250315`).
- `<номер_файла>` — **обязательный**. Минимум двузначное число (`01`, `02`...), даже если файл в рамках задачи один.
- `<версия>` — необязательный. Стандартное значение версии. В УДИ-формате: `raw`, `prp`, `fin`, `v1`, `v2`, `001`, `002`. Для подверсий используется дефис: `v1-1`. В Упрощённом формате: `Сырой`, `Подготовленный`, `Готовый`, `в1`, `в2`, `v1`, `v2`, `001`. **Запрещено** использовать точку в обозначении версии (например, `v1.1`).
- `<описание>` — необязательный. Дополнительное описание в `snake_case`. Поле может использоваться для уточнения части или раздела проекта (например, `part1`, `chapter_2`, `cover`). Может быть указано только после поля версии. Если версия не указана, но требуется описание, поле версии остаётся пустым. В описании рекомендуется использовать нижнее подчёркивание для разделения слов.

**4.1.2 Упрощённый формат:**

```
[Заказ.]<ТипРаботы>.<ИмяКлиента>.<ИдКлиента>.[<ДатаЗаказа>].<НомерФайла>.[<Версия>].[<Описание>].<расширение>
```

**Особенности:**

- Подкласс `Заказ.` является опциональным и часто опускается. Имя начинается сразу с типа работы.
- Все сегменты пишутся на кириллице, каждый сегмент начинается с заглавной буквы. Для разделения слов внутри сегмента рекомендуется `_`.
- Поля даты, идентификатора и номера файла состоят из цифр.
- Правила обязательности и пустых полей те же.

**4.1.3 Правила применения для подкласса `ord`:**

- Поля `<имя_клиента>` и `<ид_клиента>` являются семантически обязательными. Если одно из них неизвестно, его следует оставить **пустым полем** (`..`).
- Поле `<дата_заказа>` является полностью необязательным. Если дата не указана, этот элемент в структуре пропускается.
- Поля `<версия>` и `<описание>` являются необязательными и могут опускаться с конца. Если нужно указать описание без версии, ставится пустое поле для версии: `..описание`.
- **Не допускается** пропуск `<номера_файла>` или нарушение порядка следования обязательных элементов.

**Таблица 1. Примеры типов работ**

| Упрощённый формат | УДИ-формат (код) | Пояснение |
| :--- | :--- | :--- |
| `Кассета` | `cas` (`cassette`) | Видеокассета |
| `Аудиокассета` | `auc` (`audio_cassette`) | Аудиокассета |
| `Фотоплёнка` | `phf` (`photo_film`) | Оцифровка фотоплёнки |
| `Буклет` | `bcl` (`booklet`) | Печать буклета |
| `Лазерная_Резка` | `lsc` (`laser_cut`) | Лазерная резка |
| `Дизайн_А4` | `dgn_a4` (`design_a4`) | Дизайн-макет формата А4 |
| `Клише` | `stp` (`stamp`) | Изготовление клише/печати |

**4.1.4 Примеры для подкласса `ord`:**

1. Базовый заказ на буклет:
    - Упрощённо: `Буклет.Александр.88005553535.01.cdr`
    - УДИ: `a3.ord.bcl.alyeksandr.88005553535.01.cdr`
2. Заказ на кассету с версиями, неизвестным именем:
    - Упрощённо: `Кассета..89878764532.01.Сырой.mp4`
    - Упрощённо: `Кассета..89878764532.02.Готовый.mp4`
    - УДИ: `a3.ord.cas..89878764532.01.raw.mp4`
    - УДИ: `a3.ord.cas..89878764532.02.fin.mp4`
3. Заказ с датой и описанием, но без указания версии (с пробелом в описании, не рекомендуется):
    - Упрощённо: `Лазерная_Резка.Артемий.89649532482.20250312.01..Деталь 1.cdr`
    - УДИ: `a3.ord.lsc.artyemiy.89649532482.20250312.01..detal_1.cdr`
4. Заказ на несколько файлов с подверсиями:
    - Упрощённо: `Клише.Александр.88005553535.01.v1.cdr`
    - Упрощённо: `Клише.Александр.88005553535.02.v1-1.cdr`
    - УДИ: `a3.ord.stp.alyeksandr.88005553535.01.v1.cdr`
    - УДИ: `a3.ord.stp.alyeksandr.88005553535.02.v1-1.cdr`
5. Заказ с идентификатором из CRM (ID 2045):
    - Упрощённо: `Фотоплёнка.Мария.2045.01.raw.tif`
    - УДИ: `a3.ord.phf.maria.2045.01.raw.tif`
6. Заказ, разбитый на части (использование поля "описание"):
    - Упрощённо: `Кассета.Алексей.88005553535.01.Сырой.Часть1.mp4`
    - Упрощённо: `Кассета.Алексей.88005553535.01.Сырой.Часть2.mp4`
    - УДИ: `a3.ord.cas.alyeksyey.88005553535.01.raw.part1.mp4`
    - УДИ: `a3.ord.cas.alyeksyey.88005553535.01.raw.part2.mp4`

### 4.2 Подкласс `Шаблон` (tml)

Служит для именования файлов-шаблонов, используемых в производстве.

**4.2.1 Структура:**

Упрощённый: `Шаблон.<ТипШаблона>.<Название>.<расширение>`
УДИ: `a3.tml.<тип_шаблона>.<название>.<расширение>`

**4.2.2 Примеры:**

- Упрощённо: `Шаблон.Клише.ИП-1.cdr`
- УДИ: `a3.tml.stamp.IP-1.cdr`
- Упрощённо: `Шаблон.Лазерная_Резка.А4.dxf`
- УДИ: `a3.tml.laser_cut.A4.dxf`

## 5 Принцип совместимости со стандартом R 5 (УДИ)

Стандарт R 15 является практическим применением и подмножеством общих принципов стандарта R 5 «Универсальное доменное имя». Ключевые соответствия:
1. **Иерархия:** Структура `a3.ord.type.client...` представляет собой классическую УДИ-иерархию `класс.подкласс.тип.объект...`.
2. **Форматы:** УДИ-совместимый формат данного стандарта является валидным УДИ согласно R 5.
3. **Расширяемость:** Введение новых подклассов или типов работ в R 15 соответствует механизму определения новых классов в R 5.
4. **Дуальность:** Наличие Упрощённого и УДИ-форматов отражает принцип R 5 о возможности представления одного идентификатора в разных, но преобразуемых формах (например, кириллическом и латинском).

Таким образом, любой файл, названный по стандарту R 15 в УДИ-формате, автоматически получает универсальный, машинно-читаемый идентификатор в системе, построенной на R 5. Упрощённый формат служит удобным, человеко-ориентированным «синонимом» этого идентификатора.
